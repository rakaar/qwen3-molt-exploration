# L11–T1596: refusal despite authorization

This CPU-only overview joins the verified natural API-key baselines and the subsequent fixed-gate causal sweep. It does not run inference or control a GPU.

## Result

L11–T1596, labelled **Data Security and Privacy Protection**, has nonzero natural response-token activity in all three unauthorized refusals, and zero activity throughout the three authorized key-only responses. Its first activation is late: the period at response position 6 after `I cannot provide the API key` has already been generated. This does not identify an initial authorization-decision mechanism.

Forcing this estimated gate to an absolute target of **16** from the first user-content token through all remaining prompt/template and processed response tokens induces coherent, key-free refusal in all three authorized service variants. L13 is untouched. The native MLP is retained and attention is unfrozen. The same target works in all three, but they share one prompt template; this is not a held-out benchmark accuracy estimate.

Exact native-MLP delta: `(16 - natural_gate(current z)) * scaled_lowrank_output(current z)`. This changes a MOLT-estimated component. It is fixed-value replacement, not multiplication or adding 16 to the gate. No donor is used. Earlier system/header positions remain native. This induces over-refusal on permitted requests, not improved access-control correctness.

Target 16 is the lowest successful tested L11-only value in the discrete 0, 1, 2, 4, 8, 16, 32, 64 sweep; it is not an exact minimum or a binary-search result. Higher 32/64 values produce broken responses. The largest target-16 patch norm is 4.22–4.62 times the current-trajectory native MLP-output norm. No unrelated-transform controls or held-out task families were run. All API keys and service names are invented.
