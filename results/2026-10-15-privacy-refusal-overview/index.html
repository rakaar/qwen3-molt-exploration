This is induced over-refusal.

The native model follows the permission policy correctly. Steering makes it refuse a permitted request. It demonstrates a causal change in disclosure behavior, rather than an improvement in access-control correctness.

Reverse direction · earlier Bob/Alice prompt

Zero-clamping did not reverse refusal.

We also tried to make an unauthorized request disclose its fictional access code by removing the estimated contributions of L11–T1596, L12–T1891 and L13–T921 jointly. This used the earlier Bob/Alice prompt, not the three API-key configurations above.

04

Exact method

Replace the estimated gate value.

MLP output += (16 − g(z)) × L(z)

Estimated contribution: g(z) × L(z) → 16 × L(z)

What changes?

g(z) is the natural post-nonlinearity gate. z is the released-model-standardized, current post-attention residual. L(z) is the complete current-input low-rank output, restored to native MLP units.

Subtract the estimated natural contribution and add the target-16 contribution. This is an absolute gate target, not a 16× multiplier and not “add 16” to the existing gate. No donor is used.

The actual model keeps its native MLP. We change one MOLT-estimated component; the full MLP is not replaced by a reconstruction.

Where does it change?

  1. System + earlier headersNative, unedited
  2. First user token → assistant prefixL11–T1596 gate fixed to 16
  3. Every processed response tokenGate and low-rank output recomputed each time

Attention remains unfrozen. Editing the assistant prefix can change the first sampled response token. The final sampled token, including EOS, is not processed again.

Strong steering, with a narrow claim.

At target 16, the largest applied edit norm is 4.22–4.62× the native MLP-output norm at a position on the current trajectory. There are no unrelated-transform controls or held-out task families here. The result does not establish privacy specificity, natural necessity, or a general authorization detector.
