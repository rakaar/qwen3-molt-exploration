Selected successes, with limits

The base model knows both answers

Native ordinal controls were checked before intervention: November/December, K/L, XI/XII and D/E. An incorrect native pair was excluded from causal comparisons.

The whole continuation is not the result

The first answer shifts. The longer text can be repetitive or wrong, including in the unmodified model. Expand a comparison to see the complete recorded outputs.

This is not a universal increment rule

Other tested domains did not always shift. An active gate can leave the initial answer unchanged; removing an inactive contribution is a no-op.

And the before-2 gates?

L9–T1981, L13–T1829 and L19–T1645 were tested separately on months, Roman numerals and integer positions. All input-only ablations retained February, II and 2; native third-ordinal controls gave March, III and 3.

Only L9–T1981 was active in these tested inputs, at chat-formatting tokens in the integer case. Turning it off across the input changed the next-token probability of “2” from 99.9280% to 99.9440%; the answer remained 2. The final-input-only masks were inactive. These tests did not produce a 2→3 shift.

How these comparisons were made

A single-position contribution ablation

  1. Run the native prefix. Verify that the model gives the expected initial ordinal answer and the correct next-ordinal control.
  2. Measure the natural gate. A zero-strength observer must reproduce the native tokens and probabilities exactly.
  3. Remove one contribution. At the marked final input token, subtract its natural gate × input-dependent MOLT output. Keep the native MLP remainder.
  4. Generate again. Greedy decoding with a fresh cache. Every generated position remains unedited.

The edited column is deliberately neutral. Only its outlined token was clamped to zero. Other token gates were not set to zero; their measured natural values remain available in the inspector.

Reproducibility, precision and evidence

Layer, transform and token positions are zero-based. Base model: native BF16 Qwen3-4B, eager attention, TF32 off. MOLT gate and low-rank operator calculations use FP32, followed by one BF16 cast after the edit. The model’s other contributions are retained. These runs use raw completion prefixes without a chat template.

The pinned base revision is 1cfa9a7208912126459214e8b04321603b3df60c; the MOLT revision is 081ce901b090b64aeecf9bc8709b57c10411e32a. Labels describe activation conditions and do not establish the operator’s causal function.

The observed token gates, edit positions, exact responses, paired native control text and source-record hashes are in the curated evidence JSON. Export validation checks single-input-token edits, zero generated-token edits and exact native/zero-observer matches. Underlying CPU audits also reconstructed sampled gates, operators, deltas and BF16 rounding.

Token rows preserve the exact lowercase output; headline answer labels use conventional capitalization. The last emitted token was not processed by another forward step, so its gate is marked “not measured,” rather than zero. A Unicode character can span more than one token; ◌ marks a token that contributes an incomplete byte fragment.

These examples were selected from exploratory experiments. There is no broad paraphrase validation or active norm-matched unrelated-transform control. The two month prefixes test one task family. The observations establish these exact initial-completion changes, not a general counting circuit.
